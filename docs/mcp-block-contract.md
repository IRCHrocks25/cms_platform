# Sites MCP block page contract (CMS-71)

Block-backed pages have a shell template and ordered instances in `content.regions`. `get_page_html` returns the shell HTML and its template version/etag. It does not contain rendered blocks. Call `list_blocks(site, page?)` to discover every stored instance ID, including fieldless layout blocks and nested children. It returns a preorder list with each instance's type, parent ID, region, zero-based position within that region, depth, `available` flag, and current content etag. For a nested block, `region` names a slot on `parent_id`. A retired or unallowlisted type still appears with `available=false`, but remains unavailable to field and HTML edit tools. Duplicate IDs or malformed trees return an error instead of ambiguous addresses. Classic pages return an empty list. `get_block_html(site, instance_id, page?)` returns a rendered fragment for one available instance plus the current **content** etag. Nested children appear in that fragment; edit each child by its own instance ID.

`get_page` enumerates shell fields and allowlisted instance fields. A block field ID is `<instance-id>.<field-name>` (for example `blk_1234abcd.title`). The instance ID remains the address across reorders, including nested blocks. Two instances of the same type have separate IDs. Deleted instances are unavailable. `get_content` accepts the same ID; `patch_content` writes one field after comparing `if_match` with the current content etag. It supports home and block-backed inner pages, records a content version, and uses the current allowlist. GHL embed fields must use `set_embed_slot` and its tenant form checks. Classic page behavior remains unchanged.

`push_block_html(site, instance_id, html, if_match, page?)` accepts the fragment returned by `get_block_html`, with changes only to text or richtext contents belonging to that instance. The complete fragment must preserve the wrapper, all editable markers, attributes, noneditable markup, and nested child blocks. It compares the current content etag, saves the new field values as a content version, and returns a new content etag. A stale etag returns HTTP 409. Richtext uses the renderer's existing sanitizer. Form, link, image, code, style, and structure edits in the fragment are rejected. To edit those fields use the established field tool and safeguards; structural changes use the validated visual editor.

`push_page` rejects an existing block-backed page or an explicit block-shell template before changing any template, region, or version. `allow_field_loss` does not bypass this contract. It remains available for classic pages and for creating a new raw inner page. This prevents a shell replacement from silently duplicating, orphaning, or hiding instances.

Connector structural mutation is tracked separately in CMS-73. The copy API in this PR does not satisfy the full CMS-67 connector structure and installed-account acceptance criteria.

Template and content etags are separate. `get_page_html.etag` guards `push_page` on classic pages; `get_page.content_etag` and `get_block_html.content_etag` guard content edits. `get_block_html` always reads the current block type source. There is no historical block fragment write or source replacement through MCP.
