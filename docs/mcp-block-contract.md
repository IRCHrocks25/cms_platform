# Sites MCP block page contract (CMS-71)

Block-backed pages have a shell template and ordered instances in `content.regions`. `get_page_html` returns the shell HTML and its template version/etag. It does not contain rendered blocks. Call `list_blocks(site, page?)` to discover every stored instance ID, including fieldless layout blocks and nested children. It returns a preorder list in shell region DOM order, then stored-only regions, with each instance's type, parent ID, region, zero-based position within that region, depth, `available` flag, and current content etag. For a nested block, `region` names a slot on `parent_id`. A retired or unallowlisted type still appears with `available=false` and remains unavailable to field and HTML tools; available siblings can still be read and edited. Duplicate IDs or malformed trees return an error instead of ambiguous addresses, including when an unavailable block reuses an available block's ID. Classic pages return an empty list. `get_block_html(site, instance_id, page?)` returns a rendered fragment for one available instance plus the current **content** etag. Nested children appear in that fragment; edit each child by its own instance ID.

`get_page` enumerates shell fields and allowlisted instance fields. A block field ID is `<instance-id>.<field-name>` (for example `blk_1234abcd.title`). The instance ID remains the address across reorders, including nested blocks. Two instances of the same type have separate IDs. Deleted instances are unavailable. `get_content` accepts the same ID; `patch_content` writes one field after comparing `if_match` with the current content etag. It supports home and block-backed inner pages, records a content version, and uses the current allowlist. GHL embed fields must use `set_embed_slot` and its tenant form checks. Classic page behavior remains unchanged.

`push_block_html(site, instance_id, html, if_match, page?)` accepts the fragment returned by `get_block_html`, with changes only to text or richtext contents belonging to that instance. The complete fragment must preserve the wrapper, all editable markers, attributes, noneditable markup, and nested child blocks. It compares the current content etag, saves the new field values as a content version, and returns a new content etag. A stale etag returns HTTP 409. Richtext uses the renderer's existing sanitizer. Form, link, image, code, style, and structure edits in the fragment are rejected. To edit those fields use the established field tool and safeguards; use the bounded structural tools below or the visual editor for structure.

## Bounded structure tools (CMS-73)

Each write requires `site`, the current `content_etag` as `if_match`, and optional `page` (omit for home). Call `list_blocks` after a write to see the new order and etag. The tools lock the home or inner page before checking the etag; stale writes return HTTP 409. They return the new content etag, page URL, and affected instance ID. Writes create MCP content versions through the shared undo service and apply published GHL form safeguards before persistence. Classic pages reject these operations.

- `add_block(block_type, region, position, parent_id?)` creates an allowlisted block with a fresh ID and schema defaults. `parent_id` omitted/null addresses a body shell region; otherwise `region` must name a slot declared by that available layout block. `position` is zero-based and may equal the destination length. Fieldless layouts are listed like every other block.
- `remove_block(instance_id)` removes an available block and its children. A published form in that subtree prevents removal; the caller must unpublish through the normal workflow first.
- `move_block(instance_id, region, position, parent_id?)` preserves an available block's ID, fields, and children. `position` is measured in the destination after removing the source. Cycles, missing slots, and moves that exceed nesting depth reject before mutation.
- `append_block_richtext(field, operation, text)` accepts `operation="paragraph"` or `operation="list_item"` and plain text of 1–500 characters. It appends a `<p>` or a `<li>` in a trailing `<ul>` (creating the list if needed) to a richtext block field hosted by a flow container. Text is escaped; HTML and structural markup are never accepted as input. Inline hosts such as `<p>` and non-richtext fields reject. The result is capped at 16,000 characters and 80 paragraphs/list items.

Block edits are limited to body shell regions and declared nested layout slots, at most 40 instances per page and depth 2. Header/footer navigation stays with the existing editor. Unallowlisted or retired instances and descendants of retired layouts cannot be targeted. Duplicate stored IDs fail closed. These tools do not accept arbitrary block HTML, CSS, form IDs, or whole-region replacement.

`push_page` rejects an existing block-backed page or an explicit block-shell template before changing any template, region, or version. `allow_field_loss` does not bypass this contract. It remains available for classic pages and for creating a new raw inner page. This prevents a shell replacement from silently duplicating, orphaning, or hiding instances.

The bounded structural tools satisfy CMS-73's connector contract. Staging browser and real installed-account acceptance still need authorized environments; the copy API alone did not complete CMS-67.

Template and content etags are separate. `get_page_html.etag` guards `push_page` on classic pages; `get_page.content_etag` and `get_block_html.content_etag` guard content edits. `get_block_html` always reads the current block type source. There is no historical block fragment write or source replacement through MCP.
